❓
사전접수란?
왜 필요한가 · 진행하지 않으면 발생하는 문제
▼
1사전접수가 필요한 이유
  • 한 번에 다수의 고객이 하나의 쇼핑몰로 접속하면 트래픽 부하 발생
  • 서버 내 부하로 인해 원활한 쇼핑몰 사용 불가
  • 준비한 이벤트가 정상 진행되지 않아 이벤트 망칠 위험 존재
💡
대형 광고·언론 홍보·이벤트를 진행할 때는 사전접수와 함께 진행하는 것이 필수. 관련 동영상 가이드: "대형광고, 언론홍보, 이벤트를 진행하려고 합니다. 주의사항이 있나요?"
🛣️
사전접수 경로
신청서 작성 · 신청 현황 조회
▼
[관리자 어드민] 프로모션 > 이벤트 모니터링 신청
1신청서 작성 절차
프로모션 메뉴 클릭 → 하단 이벤트 모니터링 신청 → 새창 노출 → 신청서 작성하기 클릭
2신청 현황 조회
  • 이벤트 및 광고 모니터링 창에서 신청현황 조회 클릭
  • 신청한 내용 및 상태 확인 가능
📅
신청은 언제까지?
7영업일 이전 신청 권장 · 급박한 요청 주의
▼
1권장 신청 기한
  • 사전접수는 빠를수록 좋음
  • 늦어도 7영업일 이전 신청이 베스트
⚠️
사전접수를 급박하게 요청하는 경우 예상치 못한 상황에 대한 대응이 어려울 수 있음. 반드시 기간 내 신청 필수.
🔄
이벤트 날짜가 변경된 경우
기존 신청 후 날짜 수정 절차
▼
1처리 절차
신청 가능한 가장 빠른 날짜로 신청 → 변경 요청 날짜 기재하여 1:1문의 접수 → 유선 통화로 날짜 수정 진행 → 고객에게 공유
📌
이벤트가 급박하게 변경된 경우, 대응이 어려울 수 있다는 점을 고객에게 필수 안내.
긴급 / 유선 인입 대응
📞
사전접수 유선 인입 시 대응
진행 일정별 처리 기준
▼
1영업일 기준 3일 이후 진행 이벤트
  • 관리자 어드민 > 프로모션 > 좌측 하단 이벤트 모니터링 신청 배너 클릭
  • 사전접수 신청을 통해 신청 요청
2영업일 기준 2일 이후 진행 이벤트
신청 가능한 가장 빠른 날짜로 사전접수 → 1:1 문의 게시판 통해 실제 진행 일자/시간 기재 → 수정 요청
3영업일 기준 익일 ~ 당일 진행 이벤트
  • 유선 통화로 사전접수 경로 및 신청 안내 진행
  • 접수 완료 후 ERP > 시스템 확인 요청 > 요청현황 내 아이디 검색 > 상세정보 클릭
  • 실제 진행하는 일자 및 시간으로 수정 후 저장
  • ERP 수정 내용 고객과 최종 싱크 후 통화 종료
  • 이후 양식에 맞춰 업무방에 공유
⚠️
영업일 기준 최소 3~7일 전 접수해야 원활한 대응 가능. 긴급 접수 시 원활한 대응이 어려울 수 있다는 점 필수 안내.

서버부하 · 웹가속기
🚨
서버부하 발생 시 대응
동일 증상 확인 · 정보 수집 · 공유
▼
1사전접수 미실시 시 발생 문제
  • 사전접수 없이 이벤트 진행 시 서버 증설 등 대응 불가
  • 이벤트 진행 쇼핑몰 + 동일 서버 사용 쇼핑몰들의 홈페이지 및 관리자 어드민 접속 불가 가능성
2접속 지연/불가 문의 인입 시 대응
고객 쇼핑몰/어드민 접속 시도 → 동일 증상 여부 확인 → 정보 수집 및 공유
  • 고객의 쇼핑몰 및 관리자 어드민에 직접 접속 시도
  • 동일하게 접속 지연/불가 여부 우선 확인
3동일 증상 또는 다수 인입 시 수집 정보
항목내용
아이디 / 서버정보해당 고객들의 쇼핑몰 아이디 및 서버 정보
접속 불가 시간대증상 발생 시작/종료 시각
접속 불가 범위홈페이지만 불가인지, 관리자 어드민도 불가인지

웹가속기
캐시서버 · 사이트캐시 삭제 · 제거 불가
▼
1웹가속기란?
  • 사이트 반응속도 개선을 위해 설치하는 서비스
  • 캐시서버라고도 불리며, 원본 서버의 업무를 각 캐시서버가 나눠서 수행
  • 트래픽 분산으로 서버 부하 감소 및 응답속도 향상
2지연시간 발생 가능성
  • 캐시서버를 통해 서비스되므로 쇼핑몰 정보 변경 시 고객 브라우저 전달까지 지연시간 발생 가능
  • 지연 발생 항목: 상품 등록/수정, 옵션 등록/수정, 디자인 변경 등
3빠른 확인이 필요한 경우
  • 관리자 어드민 상단의 사이트캐시 삭제 클릭
  • 캐시 삭제 후 즉시 변경 확인 가능
🚫
설치된 웹가속기는 제거 불가. 신청 전 충분한 검토 필요.
